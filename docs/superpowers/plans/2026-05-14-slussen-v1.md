### Task 2: `AwaitOps` — `CompletionStage[T]` → direct-style

**Files:**
- Create: `src/main/scala/slussen/AwaitOps.scala`

- [ ] **Step 1: Write `AwaitOps.scala`**

```scala
package slussen

import gears.async.{Async, Future}
import java.util.concurrent.{CompletionException, CompletionStage}

/** Direct-style bridge for any `java.util.concurrent.CompletionStage`.
  *
  * Two extension methods:
  *   - `.await` suspends the current Async fiber and returns the value (or
  *     rethrows the underlying failure).
  *   - `.asFuture` produces a gears `Future[T]` for use with `race`, `select`,
  *     or `Future.zip`.
  *
  * On Async-scope cancellation, the underlying `CompletableFuture` is
  * `cancel(true)`-ed. Note that for Redis commands already on the wire, the
  * server may still execute the command — there is no "unsend".
  *
  * `CompletionException` is unwrapped to its cause: this is a
  * `CompletableFuture` quirk; bridging is the right place to hide it.
  */
extension [T](cs: CompletionStage[T])
  def await(using Async, Async.Spawn): T =
    cs.asFuture.await

  def asFuture(using Async, Async.Spawn): Future[T] =
    Future.withResolver[T]: r =>
      cs.whenComplete: (v, err) =>
        if err == null then r.resolve(v)
        else r.reject(unwrapCompletion(err))
      r.onCancel: () =>
        val _ = cs.toCompletableFuture.cancel(true)

private def unwrapCompletion(t: Throwable): Throwable = t match
  case ce: CompletionException if ce.getCause != null => ce.getCause
  case other                                          => other
```

> **API note:** `Future.withResolver` in gears requires the calling context to have a `Spawn` capability so the future can register itself in a completion group; that is why both `await` and `asFuture` require `Async.Spawn`. The `Future.await` we call on the last line comes from the extension `Source[Try[T]].await` in `gears.async.Async` (line ~220) and rethrows on `Failure`. If the gears version pulled in turns out to expose a different signature (e.g., does not require `Spawn` on `withResolver`), match the gears API exactly and remove the extra capability.

- [ ] **Step 1: Write the initial `Slussen.scala` (just `client` and `connect`)**

```scala
package slussen

import gears.async.Resource
import io.lettuce.core.{RedisClient, RedisURI}
import io.lettuce.core.api.StatefulRedisConnection
import io.lettuce.core.codec.RedisCodec

/** Top-level entry points for slussen.
  *
  * `client` and `connect` return gears `Resource`s, so lifecycle is structured-
  * concurrency-correct: `.use` guarantees release on cancellation or exception.
  *
  * Creating a `RedisClient` is expensive (owns the Netty event-loop group).
  * Reuse one per application; create many connections from it.
  */
object Slussen:

  /** A `Resource` over a Lettuce `RedisClient`. Release calls `.shutdown()`
    * (Netty quiet period applies; expect ~100ms in tests, configurable on the
    * underlying client if needed).
    */
  def client(uri: RedisURI): Resource[RedisClient] =
    Resource(
      RedisClient.create(uri),
      c => c.shutdown()
    )

  /** A `Resource` over a `StatefulRedisConnection[K, V]`. The codec controls
    * key/value (de)serialization — pass `io.lettuce.core.codec.StringCodec.UTF8`
    * for the common String/String case.
    */
  def connect[K, V](
      c: RedisClient,
      codec: RedisCodec[K, V]
  ): Resource[StatefulRedisConnection[K, V]] =
    Resource(
      c.connect(codec),
      conn => conn.close()
    )

end Slussen
```

> **API confirmation (Resource):** The gears `Resource.apply` we use here has signature
> `inline def apply[T](inline alloc: Async ?=> T, inline close: T => Async ?=> Unit): Resource[T]`
> (see `gears/shared/src/main/scala/async/Resource.scala:86`). The two lambdas above match.
>
> **Naming note:** `RedisClient.create` is overloaded; passing a `RedisURI` selects the typed overload. Users that want to pass a `String` URI can use `RedisURI.create("redis://...")` themselves — slussen does not duplicate Lettuce's parser.

```scala
package slussen.internal

import gears.async.UnboundedChannel
import io.lettuce.core.pubsub.RedisPubSubListener
import slussen.Message

/** Adapts Lettuce's listener interface to a gears UnboundedChannel.
  *
  * `sendImmediately` is non-blocking and unbounded, so the Netty event-loop
  * thread that delivers messages is never blocked by a slow consumer. The
  * trade-off is memory: a backlogged consumer can grow the buffer without
  * bound. Documented in the spec.
  *
  * Pattern subscribe (`PSUBSCRIBE`) is intentionally not handled in v1 —
  * `psubscribed`/`punsubscribed`/`message(pattern, channel, body)` are no-ops.
  */
private[slussen] final class ListenerAdapter[K, V](
    ch: UnboundedChannel[Message[K, V]]
) extends RedisPubSubListener[K, V]:

  override def message(channel: K, body: V): Unit =
    ch.sendImmediately(Message(channel, body))

  override def message(pattern: K, channel: K, body: V): Unit = ()
  override def subscribed(channel: K, count: Long): Unit       = ()
  override def psubscribed(pattern: K, count: Long): Unit      = ()
  override def unsubscribed(channel: K, count: Long): Unit     = ()
  override def punsubscribed(pattern: K, count: Long): Unit    = ()
```

- [ ] **Step 2: Append `Message` + `subscribe` to `Slussen.scala`**

After Task 3 the file ends with `end Slussen`. Replace it so the full file reads:

```scala
package slussen

import gears.async.{ReadableChannel, Resource, UnboundedChannel}
import io.lettuce.core.{RedisClient, RedisURI}
import io.lettuce.core.api.StatefulRedisConnection
import io.lettuce.core.codec.RedisCodec
import slussen.internal.ListenerAdapter

/** A pub/sub message: which channel it came in on, and the body. */
final case class Message[K, V](channel: K, body: V)

object Slussen:

  def client(uri: RedisURI): Resource[RedisClient] =
    Resource(
      RedisClient.create(uri),
      c => c.shutdown()
    )

  def connect[K, V](
      c: RedisClient,
      codec: RedisCodec[K, V]
  ): Resource[StatefulRedisConnection[K, V]] =
    Resource(
      c.connect(codec),
      conn => conn.close()
    )

  /** Subscribe to one or more channels.
    *
    * Returns a `Resource[ReadableChannel[Message[K, V]]]`. The Resource owns a
    * dedicated `StatefulRedisPubSubConnection` and the listener wiring; on
    * close it `unsubscribe()`s and closes the connection. Messages still in
    * the buffer at close time are silently dropped.
    *
    * The returned channel is read-only — pub/sub messages flow in one
    * direction (server → client) per Redis semantics.
    */
  def subscribe[K, V](
      c: RedisClient,
      codec: RedisCodec[K, V],
      channels: K*
  ): Resource[ReadableChannel[Message[K, V]]] =
    Resource(
      {
        val conn = c.connectPubSub(codec)
        val ch   = UnboundedChannel[Message[K, V]]()
        conn.addListener(ListenerAdapter(ch))
        conn.sync().subscribe(channels.toArray*)
        (conn, ch)
      },
      { case (conn, _) =>
        try conn.sync().unsubscribe()
        finally conn.close()
      }
    ).map { case (_, ch) => ch }

end Slussen
```

> **Type note:** `Resource[(Conn, UnboundedChannel[Message[K, V]])].map(_._2)` yields `Resource[UnboundedChannel[Message[K, V]]]`. Since `UnboundedChannel` extends `ReadableChannel`, this widens cleanly to the declared `Resource[ReadableChannel[Message[K, V]]]` (covariance on `ReadableChannel[+T]` plus `T` invariance on `Message` are both fine here).
>
> **Varargs note:** `RedisPubSubCommands#subscribe` takes a Java varargs `K...`. The Scala 3 way to pass a Scala vararg through is `channels.toArray*`. If the compiler complains about array element types (e.g., for primitives), explicitly construct via `channels.toArray(using ClassTag[K](...))`. For the common `String` codec this is not an issue.

- [ ] **Step 1: Write `README.md`**

```markdown
# slussen

A Scala 3 [direct-style](https://github.com/lampepfl/gears) Redis client. Slussen is a thin layer over [Lettuce](https://github.com/redis/lettuce) — Lettuce does the protocol, Netty I/O, pipelining, and pub/sub; [gears](https://github.com/lampepfl/gears) does the suspension and structured concurrency; slussen bridges the two.

No monads, no `F[_]`, no `IO`. Plain values, plain exceptions, `using Async`.

## Add to your build

```scala
libraryDependencies ++= Seq(
  "ch.epfl.lamp" %% "gears"        % "0.2.0",
  "io.lettuce"    % "lettuce-core" % "6.5.0.RELEASE"
)
```

Requires JDK 21+ and Scala 3.

## GET / SET

```scala
import gears.async.*
import gears.async.default.given
import io.lettuce.core.RedisURI
import io.lettuce.core.codec.StringCodec
import slussen.*

@main def example(): Unit = Async.blocking:
  Slussen.client(RedisURI.create("redis://localhost:6379")).use { client =>
    Slussen.connect(client, StringCodec.UTF8).use { conn =>
      val commands = conn.async()
      commands.set("hello", "world").await
      val value = commands.get("hello").await
      println(value) // "world"
    }
  }
```

`.await` suspends the current gears fiber; `.asFuture` is also available if you want to `race`/`zip` Redis calls with other futures.

## Pub/sub

```scala
import gears.async.*
import gears.async.default.given
import io.lettuce.core.RedisURI
import io.lettuce.core.codec.StringCodec
import slussen.*

@main def listener(): Unit = Async.blocking:
  Slussen.client(RedisURI.create("redis://localhost:6379")).use { client =>
    Slussen.subscribe(client, StringCodec.UTF8, "events").use { channel =>
      // Read messages forever (until something cancels this fiber).
      while true do
        val msg = channel.read()
        println(s"got ${msg} on ${msg}")
    }
  }
```

The channel is an unbounded gears channel populated by Lettuce's Netty event-loop thread, so a slow consumer never blocks Netty — but a permanently slow consumer can grow memory without bound.

## Cancellation caveat

When the surrounding `Async` scope is cancelled, slussen calls `.cancel(true)` on the underlying Lettuce future. If the Redis command had already been written to the socket, **the server may still execute it** — there is no `UNSEND` in the protocol. Idempotent commands or `MULTI` are the standard remedies.

## What slussen does not do

Slussen is intentionally minimal. For anything beyond the bridge — full command surface, cluster, sentinel, master/replica, transactions, Lua scripting, connection pooling, pattern subscribe — call Lettuce directly. The Lettuce docs are at https://redis.github.io/lettuce/.
